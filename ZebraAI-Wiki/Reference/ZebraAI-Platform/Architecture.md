# Architecture
ZebraAI is a sophisticated AI system hosted in Azure. ZebraAI resides within the PME tenant, with all resources related to ZebraAI located in a dedicated subscription. The system utilizes upstream data from the SXG team, hosted in the PME tenant, and stages data in Azure AI search, including commercial cases, consumer cases, knowledge management information, and ICM information. Users with corporate credentials can access ZebraAI via a web browser, and external tools and custom web applications can interact with ZebraAI through API calls. <br>

## Data Sources
Data sources provide ZebraAI with the necessary information to function effectively. Upstream data from the SXG team and other sources is staged in Azure AI search, making it readily available for processing. This data includes commercial cases, consumer cases, knowledge management information, and ICM information, which are essential. Staging data ensures efficient retrieval and processing, enabling ZebraAI to deliver accurate and relevant results.
## User Interaction
The user interaction section facilitates seamless access to ZebraAI for users. By allowing access through web browsers and API integration, ZebraAI provides flexibility in how users interact with their experiments. This ensures that users can easily access ZebraAI's capabilities, whether through a user-friendly web interface or by integrating ZebraAI experiments into their own tools and applications.
## Experiment Structure
An experiment in ZebraAI consists of a user interface, data, parameters, the model used, and the AI prompt (instructions) Experiments involve capturing user prompts, injecting data, and sending the combined data to Azure AI services. Data for experiments is staged in Azure AI search and refreshed twice daily. Data processing is handled by Synapse for data wrangling, cleansing, and staging, and an Azure SQL database serves as the OLTP database for recording activities and saving experiments. Backend tasks, such as sending emails when an experiment or API request is approved, are handled by Logic Apps. Key Vault is employed to store secrets used in ZebraAI.  Note that secrets are not employed for authentication but are used in other areas of ZebraAI.
## Experiment Flow
The experiment flow section outlines the steps involved in defining and executing experiments. This involves defining the model, interface, data, instructions, and parameters for the experiment. Data is injected into placeholders within the experiment, and the combined data and prompt are sent to Azure AI services for processing. This detailed flow ensures that experiments are conducted systematically and efficiently, leading to accurate and meaningful results.
## Data Processing
Data processing is a critical function that prepares and manages data for experiments. Synapse is used for data wrangling, cleansing, and staging, ensuring that data is properly processed before use. The Azure SQL database serves as the OLTP system, recording activities, saving experiments, and managing transactional data. This structured approach to data processing ensures that ZebraAI operates efficiently, and that data is handled accurately.
## Backend Automation
Backend automation, managed by Logic Apps, streamlines routine tasks and processes within ZebraAI. Logic Apps handle tasks such as sending emails when an experiment or API request is approved, reducing the need for manual intervention. This automation ensures that backend processes are executed reliably and efficiently, supporting the overall functionality of ZebraAI.
## Security and Monitoring
Security and monitoring are essential functions that protect ZebraAI and ensure its reliable operation. Key Vault stores secrets and manages credentials securely, safeguarding sensitive information. Application Insights provides real-time monitoring and instrumentation, allowing for the tracking and analysis of system performance. These tools help maintain the integrity and security of ZebraAI, ensuring that it operates within a secure and monitored environment.
## External Services
External services support ZebraAI's development, deployment, and operation. Azure DevOps is used for source code storage, build management, and continuous integration and deployment. Intra ID (Active Directory) manages application registration and authentication, ensuring secure access to ZebraAI. Power BI provides reporting and data visualization, offering insights into system performance and data trends. These external services enhance ZebraAI's capabilities and support its overall functionality.
## Approval Flow
The approval flow for experiments involves designing experiments using synthetic data, fine-tuning parameters and interfaces, and submitting the experiment for approval. Once approved, experiments use real data for execution.
